# Architecture Documentation — Secure Authentication Service

## 1. System Overview

The **Secure Authentication Service** is an educational, production-inspired authentication microservice designed to demonstrate state-of-the-art defensive controls:
- **Argon2id Password Hashing (RFC 9106):** Memory-hard and time-hard password hashing.
- **Timing Invariance:** Defending against username enumeration and side-channel timing analysis.
- **MFA (RFC 6238 TOTP):** Time-based one-time password generation and replay protection.
- **Progressive Account Lockouts:** Per-account progressive delays and exponential backoffs.
- **High-Entropy Hashed Sessions:** 256-bit CSPRNG session tokens hashed with SHA-256 before storage.
- **Structured Audit Trails:** RFC 5424 compliant event logging with zero credential leakage.

## 3. Data Flow & Security Lifecycle

1. **User Registration:**
   - Client sends username, email, and password.
   - Password is validated for minimum length (12+ characters) and maximum length (512 characters).
   - Password is hashed using **Argon2id** with a unique 16-byte random salt generated by CSPRNG.
   - User entity is created in SQLite storage with `is_active=True`, `mfa_enabled=False`.
2. **Timing-Safe Login:**
   - Client submits username/email and password.
   - If user does **not** exist: The service executes a synthetic dummy Argon2id verification using a pre-calculated dummy hash.
   - If user **does** exist: The service verifies the password using `argon2.PasswordHasher.verify()`.
   - Both branches take identical execution time ($\approx 80-120\text{ms}$), completely blinding attackers from username enumeration.
   - If password is correct and MFA is enabled, a temporary `mfa_token` is issued requiring step-up authentication.
   - If password is correct and MFA is disabled, a 256-bit CSPRNG session token is generated, its SHA-256 hash stored in the DB, and the raw token returned via cookie / Authorization header.
3. **MFA Setup & Verification:**
   - Generates a 160-bit Base32 TOTP secret.
   - Emits a secure `otpauth://` URI and 10 single-use emergency backup recovery codes (each stored as a SHA-256 hash).
   - Upon successful verification of the first 6-digit TOTP code, `mfa_enabled` is set to `True`.
4. **Session Management & Revocation:**
   - Sessions expire after a configured sliding window (default 24 hours).
   - Logout immediately deletes the session hash from the database.
   - Password change or privilege escalation automatically revokes all active sessions.
